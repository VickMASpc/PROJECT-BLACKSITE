# v0.1 Acceptance — Operation Glasshouse Foundation

## Purpose

0.1 is not supposed to prove final art, explicit animation quality, guard AI, or the complete facility.

It proves that BLACKSITE can behave like a small game inside Figura.

## Acceptance criteria

### Companion

- Reina renders independently of the player.
- Reina is visible from first person because she is WORLD-parented.
- Follow works.
- Wait works.
- Reina does not repeatedly teleport to keep up.
- If she gets more than ~30 blocks away, the system admits she is lost and asks for manual recovery.
- Basic local obstacle steering exists.
- Disguise can visibly change the proxy.
- Persistent compromise can slow her movement.

### Mission

Fresh save:

1. INSERTION
2. SERVICE WING
3. DISGUISE
4. CHECKPOINT 1
5. RESEARCH FLOOR
6. MAINTENANCE SHAFT
7. LAB
8. CHECKPOINT 2
9. COMPLETE

The test route is generated relative to the player's initial position/facing. No facility map is required to validate 0.1.

### Contextual command proof

Checkpoint 1 must not resolve from a generic animation list.

The mission unlocks a specific special order only after the player has:

- acquired the prototype
- inspected the security logic
- reached the checkpoint beat

That order creates a persistent concealment/compromise state.

### Consequence proof

The compromise must still matter later.

Required:

- slower/careful following
- altered dialogue on research floor
- a maintenance-shaft problem
- multiple shaft solutions with different endurance/strain/normalization consequences
- second checkpoint referencing the same earlier state

### Endurance proof

At least one command must:

- consume endurance
- add strain
- persist after the interaction
- become unavailable below a hard threshold

0.1 uses **Order her to endure it** at the maintenance shaft for this proof.

### Persistence

Reloading the avatar/client must preserve:

- mission phase/step
- mission flags
- operation origin/heading
- alert
- disguise
- compromise/concealment
- endurance
- strain
- discomfort
- composure
- annoyance
- normalization
- machine-state schema values

### UI

HUD must show:

- project/mission
- phase
- objective + distance
- Reina's high-level movement/follow/disguise state
- contextual dialogue/status
- command menu when opened

Normalization must **not** be shown as a normal stat.

## Not required for 0.1

- final Reina bbmodel
- explicit final animations
- full S-Machine scene
- guard NPC AI
- camera entities
- scanner entity/model
- bespoke facility map
- voice
- multiplayer synchronization
- actual collisions/hitbox for Reina
- cinematic camera system

Those come after the controller proves itself.
